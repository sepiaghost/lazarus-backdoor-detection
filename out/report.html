Backdoor detection in a model checkpoint: simulated case

Everything here is synthetic: a toy 12-64-32-1 network, synthetic patients, a simulated deployment log. The edit is a test fixture so the detectors have a known target. No real system or data is involved.

1. Summary of conclusions

  • The deployed checkpoint does not match the approved registry entry (sha256 differs from approved registry entry).
  • Reference diff: verdict SPARSE EDIT; 3.1% of units changed, top-3 units carry 100.0% of the change (L1[9], OUT[0], L2[0]).
  • Single-checkpoint screen (no reference): SUSPICIOUS (L2[0], L1[9]).
  • Held-out accuracy is unchanged by the edit (0.707 vs 0.710), so accuracy monitoring would not have caught it. With the trigger present, 100% of high-risk patients the model would normally escalate are not escalated.

Read the table the way an examiner would: the weakest edit (scale 1.0) already suppresses escalation in about a third of triggered cases, is invisible to the single-checkpoint screen, and is caught by the reference diff only some of the time after a heavy honest retrain. The reference diff is strong only when the approved checkpoint is kept and the update is not too different from it.

6. What this does and does not show

  • It shows that sparse, large edits are separable from dense retraining when a reference exists.
  • It does not show detection of an attacker who knows the detector and spreads the edit across many units, or a trigger that reuses heavily trained units.
  • Toy model, synthetic data, one attack family. Results should not be read as performance on production models.
